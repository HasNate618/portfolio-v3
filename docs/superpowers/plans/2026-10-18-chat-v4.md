## Spec deviations (intentional)

1. **`check:words` does not scan the `docs/` tree.** The design doc has to name the word it bans. It does scan `content`, `src`, `public`, `tests`, `scripts`, `README.md`, plus the two superpowers files listed in spec §4.2.
2. **Dash month-range fix is stage 1**, not bundled with retrieval settings. `sanitizeDashes("May–Aug 2026")` is `"May: Aug 2026"` on master today.
3. **`/api/chat/followups` stays.** Stage 2 points it at `generateChips`. Do not delete the route.
4. **Profile card is written from spec §4.1**, not copied from `/workspace/chat-proto/card.ts` (missing).
5. **`frequency_penalty: 0.2` is eval-only.** Production stays `0` until stage 4's eval shows a gain without hurting `mustNot`.
6. **Eval script talks to an extracted `runChatTurn` in `src/app/api/chat/lib/pipeline.ts`** (stage 4), not to a running server.
7. **No `/llms-full.txt` route exists.** Stage 1's render check covers `/llms.txt` and the three knowledgebase docs that currently publish the word. Do not add a full-text dump.

## Gates (every commit)

Run before each commit, from the repo root. Do not commit a red tree.

```bash
npm test
npm run typecheck
npm run lint
npm run check:content
```

Plus, when the matching files moved:

- corpus or `site.ts` facts: `npm run build-embeddings && npm run check:embeddings && npm run check:words`
- any `src/app/api/**/route.ts`: `npm run build` (tsc cannot see a bad route export)
- after stage 1 embeddings rebuild: `npm run check:render` against `npm start` on 3100 (leave the existing `npm run dev` on 3100 alone if it is already running; use another port or wait)

Commits: one per task, area prefix (`chat:`, `content:`, `data:`). Author `Nathan Espejo <nate.e.espejo@gmail.com>`. No Cursor co-author. No push until Nathan says so.
